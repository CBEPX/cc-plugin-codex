# cc 1.7.5 implementation plan

Approved in conversation on 2026-09-08. Execute with Superpowers TDD, task reviews,
and final independent cc/Fable review. This file records the approved behavior;
the execution ledger records progress and any necessary rulings.

## Goal and constraints

Fix oversized public reads and incomplete independent peer-worker instructions,
then close issues #25, #30, #37, #45, #46, #49. Add tracking issues for worker
instructions and the full mutation timeout. Leave #27, #38, #39 and Grok PR #36
outside this release.

- Version 1.7.5; Node >=18; no new runtime dependencies; no history migration.
- Base: v1.7.4 commit 2ed8323f2d52ce9635c25b02a7c71b468565c087.
- Reuse existing modules and node:test; no unrelated restructuring.
- Raw leases stay off argv/stdout/stderr/logs and public exports.
- Preserve independent memo sealing, exact tool-ID validation, state fencing,
  and direct-HTTPS citation validation.
- Default public read output is bounded to 8192 UTF-8 bytes, with explicit
  truncation/omission information. Full authorized JSON is explicitly exported.
- Existing durable payloads remain intact. Summary/truncated output must not
  acknowledge a full result as viewed. Failed export must not acknowledge it.
- Each nontrivial change needs a meaningful failing test before implementation.
- Use isolated test homes. No live smoke during implementation sub-tasks.

### Task 1: Bounded read views, exact export, and worker read integration

Constraints: Node >=18, no runtime dependency or durable payload migration,
8192 UTF-8 byte default public reader cap, no raw lease exposure, test-first.

Implement #46 for current and historical records in status, result, workflow-read,
workflow-list and peer-wait (JSON and human output). Inspect all callers first.
Primary owners are scripts/claude-companion.mjs, scripts/lib/render.mjs,
scripts/lib/job-control.mjs and scripts/lib/peer-orchestration.mjs; a small dedicated
read-view module is allowed if it avoids mixing serialization policy into state.
Do not put generic truncation into mutation/launch output: spawn plans must stay
complete and usable.

Keep default status purpose-specific: identifiers, state/phase, failure details,
readiness/terminal flags, useful bounded model/progress data, counts and next step.
Do not include full job results, repeated memos/checkpoints or attempt history in
status/list/poll responses. Keep existing useful top-level fields where possible;
workflow-list may wrap its list to carry totals and truncation metadata. Result
may show its complete result when within budget; otherwise visibly preview it.
Shrink fields/lists before serialization, never cut serialized JSON. Include
truncated and explicit omission information, including omitted record counts.

Add --output <path> to these five read commands. Write the exact full authorized
JSON read payload to a newly created mode-0600 file; refuse existing files and
symlinks. Return a small receipt with outputFile, bytes and sha256 (JSON if --json).
On write failure remove only an incomplete file this invocation created and do
not acknowledge viewing. Existing exported JSON consumer shapes should be kept
where possible. Never expose sibling memo before Codex memo is sealed, through
any of status/result/list/read/wait or export. Export publicly readable data,
not raw leases or hidden pre-seal fields.

Summary and truncated reads do not consume terminal notifications. Preserve
existing acknowledgment intent for successfully delivered complete results or
explicit full exports, after successful delivery. Cover failed writes as well.

Update generated initial/checkpoint/retry/synthesis read instructions and built-in
skills/runtime consumers to use short one-shot polling and explicit export when
they need complete memo/critique/final content. Exports for workers belong in a
temporary directory outside the workspace; clean them after use. Give exact
commands, have workers inspect file sections rather than cat an enormous result.
Synthesis must see complete frozen inputs, never silently synthesize a preview.
Keep fork_turns none and current epoch/lease ownership. Missing memo content
instructions and schema changes themselves are Task 2.

Tests: regression for JSON.parse on large records, valid JSON and <=8192 bytes
for both output formats and all five readers (including --all, long strings,
Unicode, arrays and >1 MiB historical records), exact JSON export/checksum,
permissions, existing-file/symlink refusal, write failure, unchanged durable
payloads, notification-view semantics, no pre-seal sibling leaks, and complete
worker checkpoint/continuation reading. Use existing peer/integration/E2E tests
and add focused helper tests as needed. Update obsolete consumer assertions to
the approved new contract. Do not run new direct stateful tests without preload
before Task 3 fixes that issue. Run focused RED/GREEN and existing affected suites;
run npm test once before commit. Record any unrelated pre-existing failures.

Update relevant CLI help/runtime docs with --output and the changed JSON default.
Commit only Task 1 changes; report exact commits, RED/GREEN and tests.

### Task 2: Peer memo contract, citation schemas, diagnostics and signal cleanup

Constraints: Node >=18, no runtime dependency or durable payload migration,
no raw lease exposure, maintain exact tool/citation safety, test-first.

Finish the worker-instructions issue: initial/retry Codex workers with fork_turns
none must receive an explicit valid memo structure: nonempty content object,
repoCitations [{path,line}] pointing to real in-workspace files/lines,
webCitations as direct HTTPS URL strings, toolEvents when appropriate. Use the
mode's existing content contract and keep all supplied brief data untrusted.
Give truthful executable instructions, not an invented peer-status alias.
Preserve Task 1 export/read integration and captured epoch/lease fencing.

For #37 update all three native peer schemas (design/research/critique), prompts,
validation-facing examples, renderers and tests to string[] webCitations. Existing
runtime accepts legacy {path,line}; preserve it for v1.7.x records/inputs. Repo
citations and HTTPS/no-userinfo/credential-query rejection remain unchanged.

For #25 retain PEER_OUTPUT_SCHEMA_UNAVAILABLE and fail before ensureClaudeReady
or spawning Claude. Add bounded allowlisted failureDetail values SCHEMA_MISSING,
SCHEMA_READ_FAILED, SCHEMA_JSON_INVALID, SCHEMA_SHAPE_INVALID through the existing
workflow diagnostic path. Do not render/persist schema contents, paths or raw
exceptions. Cover missing, unreadable, malformed and non-object schemas and
prove the fake Claude was never invoked.

For #49 fix the shared generated base64/file-backed submission recipe: EXIT,
HUP, INT and TERM all remove the mode-0600 temporary lease file; interruptions
preserve signal-derived exit codes and never continue submission after cleanup.
Use small portable POSIX-shell traps. SIGKILL is not catchable. Test the generated
recipe by executing it and interrupting the process at a controlled phase,
checking file absence, no submission and exit status; test normal exit too.

Tests must run real validators/recipes/CLI boundaries, not only string searches.
Run focused RED/GREEN and affected peer/schema/E2E suites, npm test once before
commit. Commit Task 2 only, report tests/commits/concerns.
